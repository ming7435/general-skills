# 从大纲生成可编辑手册

使用包内的 `scripts/build_manual.py` 可以从 UTF-8 JSON 生成 Word。用工作环境提供的 Python 运行，需要 `python-docx` 和 Pillow。图片路径相对于 JSON 所在目录。脚本只生成 Word；需要 PDF 时，将最终的 Word 导出并检查分页。

```text
python scripts/build_manual.py manual.json 用户使用说明.docx
```

## 最小示例

以下是虚构的场地查询工具。实际编写时，用当前工具的操作名称、材料和反馈替换示例内容。

```json
{
  "title": "场地查询助手使用说明",
  "intro": "想找几个人能坐得下的会议室，可以在聊天里说明人数和时段。",
  "assistant_name": "场地查询助手",
  "workflow": [
    {"title": "打开助手", "text": "在工作台点“场地查询”，选好办公区后开始查询。"}
  ],
  "skills": [
    {
      "name": "查空闲场地",
      "goal": "找一个适合小组讨论的会议室。",
      "inputs": ["当日场地安排（在线表格链接）"],
      "output": "指定时段的空闲会议室名单。",
      "prepare": "用当天的安排表，确认助手能够打开链接。",
      "turns": [
        {"who": "user", "text": "周三下午两点到三点，四个人开会，有空房间吗？", "files": [{"name": "周三场地安排", "type": "在线表格"}]},
        {"who": "assistant", "text": "这段时间二楼小会议室空着，有六个座位。"}
      ],
      "use": "从名单中选定房间后，再到预约入口确认。"
    }
  ]
}
```

## 字段和截图

| 位置 | 字段 | 用法 |
| --- | --- | --- |
| 全书 | `title`、`intro`、`workflow`、`skills` | 标题、用途、顺序操作和逐项功能。后两项各至少一条。可加 `setup` 说明第一次开通或登录。 |
| 操作步骤 | `title`、`text`，可选 `image`、`caption` | `setup` 和 `workflow` 均用这一结构。用原界面截图指明点击位置。 |
| 单项功能 | `name`、`goal`、`inputs`、`output` | 共同生成可编辑的能力地图。把每项输入写成用户认得的材料名称。无需上传或链接文件时传空列表 `[]`。 |
| 对话工具 | `turns`、`assistant_name` | 每条消息包含 `who`（`user` 或 `assistant`）、`text`。上传或返回的文件放在对应消息的 `files` 里；名称用 `name`，可选 `type` 写“录音”“在线表格”等。 |
| 普通软件 | `actions`、`image`、`caption` | `actions` 是按顺序列出的操作句。已有足够清楚的真实操作截图，也可只用 `image` 和图注；已有真实聊天截图同理。 |
| 成果 | `result_image`、`result_caption`、`use` | 有实际结果图时传文件路径。示范聊天以助手回复结束时，结果图放在最后的回复中。无结果图时用文字说明到哪里查看或核对结果。`use` 说明拿到后怎么用。 |
| 准备 | `prepare` | 给出最低材料、可替代版本、特殊条件或链接权限等说明，按需填写。 |

如果环境中没有可用的中文绘图字体，脚本会把示范对话写成可编辑的 Word 段落。希望生成带附件卡片的图时，加 `--font` 指向本机可用的中文字体。对话过长时，分成简短的任务示例，或保留原对话截图并截出关键部分。特别窄的长图可以分段展示，避免在手机上要反复放大。
