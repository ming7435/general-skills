# 如何编写入门页、答疑和审查现有手册

完整手册的主线是第一次使用、业务流程、能力地图、逐项操作。下面几种写法来自产品说明书专家的读者分析与 Divio 文档分类，用于选择简短的交付形式或审稿。

## 先选读者现在要走的路

| 读者要做什么 | 写法 |
| --- | --- |
| 第一次做成一件事 | 快速入门。用读者认得的材料和任务开头，只留必要的权限、入口、操作、成功信号。 |
| 已经用过工具，要完成某项工作 | 操作指南。用这项工作做标题，写出材料、动作和在哪看到结果。 |
| 想查某个文件或按钮怎么用 | 参考。放进能力地图或字段表，沿用界面中的名称，说明何时才需要它。 |
| 想弄懂为什么还要补一份材料 | 解释。写出缺的内容会影响哪个判断，将短解释放到那一步旁边。 |

如果用户只要“快速入门”，可以只交一页。比如，一个对比文稿的助手可以用一份 PDF 和一份带查看权限的在线文档演示。先说明在哪里发这两份稿件，再写一句“帮我列出有修改的段落”。若实际产品在原对话返回差异清单，最后教读者去回复里找它。普通软件则按真实菜单演示相同任务，不补编聊天。

## 常见问题与排错

问答适合一两句话能答完的问题。例：“在线文档也要下载吗？”如果该产品支持链接，可以写“直接发文档链接。分享时把查看权限开给接收方。”

遇到多步排错时从一个真实症状写起。比如项目实际出现过“无法读取附件”，先说明提示出现在哪里，再让读者检查缺哪种权限或哪一个文件，最后说明怎样确认已恢复。具体原因要能从产品说明或现有记录查到。如果只有一张报错图，就写已知现象和需要进一步确认的条件，不擅自断定原因。只在有真实问题或用户指定时添加这一节。

## 审稿时替读者做一次

- **五秒看首页。** 能否说出这是给谁用、能办成哪件事、第一步去哪儿？不明白入口，就用真实按钮名或产品名重写那一句。
- **按实际顺序走。** 跟到一个关键步骤时看看能否找到对应的界面、输入和反馈。能实测就测试。凭截图核对时只说明核对过的内容，避免承诺已验证权限、交付或业务结论。
- **读出声。** 把“在已经加入伙伴的项目群里 @ 它”改成“如果伙伴已经在项目群里，在输入框输入 @，再选中伙伴”。用同一个词称呼同一个按钮，尤其留意“它、该项、上述资料”究竟指什么。
- **检查重复。** 流程讲怎么走，能力地图帮助选功能，技能图演示一次。截图已经能说明的文件名，不必再加一张用途完全相同的表。修订某处时留下仍然有用的原图、原话和其余页面。
- **发布前开成品。** 看一段真实对话、一个长文件名、一张结果图和一个跨页表格。检查中文能读、角色没有颠倒、链接和文件形式准确、输出确实可打开。版本和日期按真实资料填写。
