# 业务事实与编排

## 从页码到一句旁白

先在工作目录建一张轻量表。每行保留“镜头或段落、拟说的结论、原页码和原句、项目或人群、时间与状态、画面依据”。再从原句推导屏幕上的简写。保留决定含义的词，例如“本轮试点”“计划”“其中”“建议”。

| 原稿里的情况 | 成片处理 |
|---|---|
| 总数、优秀子集、处理闭环率同页出现 | 屏幕先给总量，再用“其中”带出子集。百分比和完整指标名始终同框，旁白说清衡量的对象。 |
| 案例甲做到拆解，案例乙展示验证 | 给两案各自的镜头标题。在切点说清为什么换项目、前一个项目走到哪一步，随后再放验证截图。 |
| 同一能力在蓝图、试点记录、推广计划里都有描述 | 先查日期、层级和状态，用完成时描述已验证动作，用计划表述后续工作。计划页里的看板效果图入镜时标清身份。 |
| 不同页给出不同项目数量 | 回到每页的范围和统计时点。口径仍不明时，优先使用材料明确支持且对讲解足够的结论。 |
| 有多条需求分发路径、可共享的支撑能力 | 总览画分支、输入、回流或支撑关系。按章节高亮当前位置，箭头方向按原稿核对。 |
| 一张案例图片很醒目，宣传主体却是整体业务成果 | 开场标题、代表画面和结尾都指向整体成果，把案例放到它能解释的业务环节。 |

## 两种剪法

**业务讲解。** 先写给没参加项目的人。每章用一个问题带入：谁做判断、依据什么、系统里留下什么、下一个人怎么接。界面上的按钮只在它能解释业务动作时出现。复杂截图可先框出所在区域，再放大一条记录；字幕、画面标签和旁白各承担一部分信息。结尾回答开场的问题，并明确本轮验证的范围。

**成果短片。** 先定一个能在前三秒看懂的主体和成果，再选择两三处最有说服力的原始证据。每个数字连同单位与口径一起入画。限时放不下的背景细节可以交给画面或分镜文档。实测超时先改稿，再录音；检查片尾停留能否读完。

**文件带走时也能用。** 讲解稿标章节起点；目录给出章节、内容和原页码；工程中保留“镜头 → 原页 → 嵌入图片或图表 → 取景范围”。来源日期和计划表述取自这次的原稿。
